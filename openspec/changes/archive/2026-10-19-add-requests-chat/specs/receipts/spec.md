## MODIFIED Requirements

### Requirement: Вкладка «Квитанции»
Навигация шапки зависит от роли: у собственника (`OWNER`) пункты «Показания», «Квитанции» и «Заявки», у жильца (`RESIDENT`) только «Показания», у администратора (`ADMIN`) «Выставить квитанции» и «Заявки» (см. требования «Вкладка «Выставить квитанции»» и спецификацию `requests-screen`); пункт «Заявки» (у собственника и администратора) открывает вкладку заявок (см. спецификацию `requests-screen`), у жильца его нет. Клик по «Квитанции» SHALL открывать вкладку квитанций, клик по «Показания» — форму ввода показаний, активный пункт выделяется основным цветом. Вкладка квитанций содержит только список и скачивание. Активная вкладка собственника SHALL отражаться в адресе параметром `tab` (`tab=receipts` для квитанций, без параметра — показания); параметр `account` при переключении MUST сохраняться. Открытие адреса с `tab=receipts` SHALL сразу показывать вкладку квитанций и сохраняться при обновлении страницы; любое другое значение `tab` открывает показания. У жильца `tab=receipts` открывает показания; у администратора допустимы `tab=requests` (вкладка заявок) и отсутствие параметра (вкладка «Выставить квитанции»), любое другое значение, включая `tab=receipts`, открывает «Выставить квитанции». Шапка, данные лицевого счёта, их загрузка и состояния ошибок («Лицевой счёт не найден», «Не удалось загрузить данные», «К вашей учётной записи не привязан лицевой счёт») MUST быть общими для вкладок собственника и жильца.

#### Scenario: Переключение по клику
- **WHEN** собственник на экране показаний нажимает «Квитанции» в шапке
- **THEN** открывается вкладка квитанций, пункт «Квитанции» выделен основным цветом, пункт «Показания» нет, адрес содержит `tab=receipts` и прежний `account`

#### Scenario: Возврат к показаниям
- **WHEN** собственник на вкладке квитанций нажимает «Показания»
- **THEN** открывается форма ввода показаний, из адреса исчезает `tab`, `account` остаётся

#### Scenario: Прямая ссылка на вкладку
- **WHEN** собственник открывает `/?account=000000000001&tab=receipts`
- **THEN** сразу показана вкладка квитанций счёта `000000000001`

#### Scenario: Неизвестное значение вкладки
- **WHEN** адрес содержит `tab=unknown`
- **THEN** открыта форма ввода показаний

#### Scenario: Вкладка квитанций у жильца
- **WHEN** жилец открывает адрес с `tab=receipts`
- **THEN** открыта форма ввода показаний

#### Scenario: Администратор без показаний и квитанций
- **WHEN** в систему вошёл администратор
- **THEN** в навигации нет пунктов «Показания» и «Квитанции», открыта вкладка «Выставить квитанции», а адрес с `tab=receipts` её не меняет

#### Scenario: Администратор открывает заявки
- **WHEN** администратор нажимает «Заявки»
- **THEN** открывается вкладка заявок, адрес содержит `tab=requests`

#### Scenario: Счёт не найден
- **WHEN** API вернул `404` для запрошенного номера, а адрес собственника содержит `tab=receipts`
- **THEN** показано сообщение «Лицевой счёт не найден», а список квитанций не запрашивается

#### Scenario: Заявки не открываются
- **WHEN** жилец открывает адрес с `tab=requests`
- **THEN** вкладка заявок не открывается, показаны показания

#### Scenario: Заявки открываются
- **WHEN** собственник нажимает «Заявки»
- **THEN** открывается вкладка заявок, адрес содержит `tab=requests`

### Requirement: Вкладка «Выставить квитанции»
Для пользователя с ролью `ADMIN` вкладка «Выставить квитанции» SHALL быть первой из двух вкладок навигации (вторая — «Заявки»): она открывается сразу после входа и после обновления страницы, пока в адресе нет `tab=requests`, имеет заголовок «Выставить квитанции» и содержит форму публикации. Адрес вкладки параметров `tab` не получает; `account` для неё не используется. Остальным ролям пункт не показывается, вкладки с формой у них нет. Вкладка не зависит от какого-либо лицевого счёта: квартира, для которой публикуется квитанция, выбирается в форме.

#### Scenario: Вход администратора
- **WHEN** в систему вошёл администратор
- **THEN** открыта вкладка «Выставить квитанции» с формой, пункт «Выставить квитанции» выделен основным цветом, адрес без `tab`

#### Scenario: Пункта нет у остальных
- **WHEN** в систему вошёл собственник или жилец
- **THEN** пункта «Выставить квитанции» в навигации нет

#### Scenario: Обновление страницы
- **WHEN** администратор обновляет страницу
- **THEN** после восстановления сессии снова показана вкладка «Выставить квитанции»
