## Why

Жильцы должны передавать показания счётчиков воды через веб-интерфейс. В макете Figma (`communal-services`) есть экран «Ввод показаний» (фрейм `02-meter-readings`), но во фронтенде пока только стартовая страница с индикатором состояния бэкенда. Нужно воплотить макет в рабочий интерфейс.

## What Changes

- Новый экран «Ввод показаний» по фрейму `02-meter-readings` (1440×900): шапка (название ТСЖ, навигация «Показания»/«Заявки», иконки, адрес квартиры и номер лицевого счёта), заголовок страницы с периодом и сроком передачи, карточки стояков с полями горячей и холодной воды, кнопки «+ Добавить стояк», «Отправить показания», «Сбросить форму», карточка «Нужна помощь?» с контактами председателя правления.
- Каждое поле показывает предыдущее показание, а карточка стояка — номер счётчика.
- Экран становится стартовой страницей; индикатор состояния бэкенда со страницы убирается (в макете его нет).
- Фрейм `01-auth` не реализуется и не затрагивается: авторизации и маршрутизации на неё нет.
- Бэкенд и БД не меняются. Данные (адрес, лицевой счёт, стояки, предыдущие показания) берутся из локальных заглушек на фронтенде; «Отправить показания» не вызывает API (см. design.md).

## Capabilities

### New Capabilities
- `meter-readings-screen`: экран ввода показаний воды по стоякам — состав, валидация ввода, добавление стояка, отправка и сброс формы.

### Modified Capabilities

- `platform-health`: удаляется требование «Индикация состояния в интерфейсе» (эндпоинт состояния бэкенда не меняется).

## Impact

- `frontend/src/`: новые компоненты экрана и заглушка данных, изменения `App.tsx`, тема Ant Design (основной цвет `#ffb370`, фон `#fffbeb`), тесты (vitest + Testing Library).
- Новых зависимостей нет (только antd).
- Backend, БД, инфраструктура, nginx не затрагиваются.
