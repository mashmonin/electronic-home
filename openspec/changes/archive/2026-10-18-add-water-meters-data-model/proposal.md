## Why

Экран ввода показаний работает на заглушке: стояки, счётчики и предыдущие показания выдуманы на фронтенде (`getRisers()`). В БД есть квартиры (адреса), но нет счётчиков и показаний, поэтому нельзя ни показать «Пред. показание», ни сохранить новые показания. Нужна модель данных счётчиков воды.

## What Changes

- Новая таблица счётчиков воды: счётчик принадлежит одной квартире (адресу), у квартиры может быть много счётчиков; каждый счётчик — горячей (`HOT`) или холодной (`COLD`) воды, имеет номер/название.
- Новая таблица показаний: у счётчика много показаний; в показании хранится значение, дата и необязательная ссылка на **предыдущее показание** того же счётчика (первое показание ссылки не имеет).
- Целостность на уровне БД: предыдущее показание должно принадлежать тому же счётчику, не может быть самим собой, цепочка показаний линейная (одно показание — предыдущее не более чем для одного следующего, у счётчика одно первое показание).
- Признак `is_test` в обеих новых таблицах (как в остальных таблицах модели).
- Тестовые данные только для `dev`: счётчики «Тест 1» (горячая вода) и «Тест 2» (холодная вода) на тестовой квартире 1, у каждого по два показания с цепочкой «предыдущее».
- REST API и перевод фронтенда с заглушки на эти данные в изменение не входят.
