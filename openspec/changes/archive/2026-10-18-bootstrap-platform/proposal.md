## Why

Для сервиса передачи показаний ЖКУ нет ни кода, ни окружения (есть только пустой IntelliJ-скелет). Прежде чем писать доменную логику, нужен воспроизводимый каркас: бэкенд, БД, фронтенд, веб-сервер с SSL и два профиля запуска — без установки инфраструктуры на машину разработчика.

## What Changes

- Бэкенд `backend/`: Spring Boot (Java 21), Gradle, подключение к PostgreSQL, Liquibase (пустой мастер-changelog), health-endpoint.
- Фронтенд `frontend/`: React + TypeScript + Vite, компоненты только из antd, стартовая страница, проверяющая связь с бэкендом.
- Профили приложения `dev` и `prod` (конфигурация, логирование, CORS, секреты).
- Docker: Postgres, backend, сборка frontend и nginx запускаются только в контейнерах; два compose-окружения (dev и prod).
- nginx: раздаёт статику фронтенда, проксирует `/api` на бэкенд, терминирует TLS; HTTP перенаправляется на HTTPS.
- SSL: в dev — самоподписанный сертификат, генерируемый в контейнере; в prod — сертификаты, смонтированные с хоста.
- Удалить заглушку `src/main/java/org/example/Main.java` и корневой Gradle-проект заменить на `backend/`.

## Capabilities

### New Capabilities
- `runtime-profiles`: профили `dev` и `prod` и различия в их поведении.
- `containerized-infrastructure`: запуск БД, веб-сервера и приложения только в Docker, без локальной установки.
- `secure-web-access`: раздача фронтенда и API через nginx по HTTPS.
- `platform-health`: проверка работоспособности сервиса и связи с БД.

## Impact

- Новые каталоги: `backend/`, `frontend/`, `infra/` (nginx, сертификаты), compose-файлы в корне.
- Существующий корневой `build.gradle.kts`/`settings.gradle.kts`/`src/` удаляются или переносятся в `backend/`.
- Требование к машине разработчика: только Docker (JDK/Node/Postgres локально не нужны).
- Доменные функции (жильцы, счётчики, показания) — вне этого change, будут отдельными change.

## Non-goals

- Аутентификация и роли, модель счётчиков и показаний, уведомления.
- CI/CD и выбор хостинга; автоматический выпуск сертификатов (Let's Encrypt).
