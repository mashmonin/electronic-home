## Purpose

Описывает доступ пользователей к фронтенду и API через nginx по защищённому соединению HTTPS.

## ADDED Requirements

### Requirement: Доступ только по HTTPS
Сервис SHALL принимать пользовательский трафик по HTTPS с SSL-сертификатом. Запросы по HTTP MUST перенаправляться на HTTPS.

#### Scenario: Перенаправление с HTTP
- **WHEN** клиент отправляет запрос на HTTP-порт
- **THEN** он получает перенаправление на тот же адрес по HTTPS

#### Scenario: Защищённое соединение
- **WHEN** клиент открывает сервис по HTTPS
- **THEN** соединение устанавливается с использованием TLS 1.2 или выше

### Requirement: Раздача фронтенда
nginx SHALL отдавать собранное React-приложение; запросы к клиентским маршрутам, не соответствующие файлу, MUST возвращать главную страницу приложения.

#### Scenario: Открытие главной страницы
- **WHEN** пользователь открывает корневой адрес сервиса
- **THEN** загружается интерфейс приложения

#### Scenario: Прямой переход на клиентский маршрут
- **WHEN** пользователь открывает по прямой ссылке клиентский маршрут (например, `/readings`)
- **THEN** загружается интерфейс приложения, а не ошибка 404

### Requirement: Проксирование API
Запросы с префиксом `/api` SHALL проксироваться на бэкенд; бэкенд MUST NOT быть напрямую доступен снаружи контейнерной сети.

#### Scenario: Запрос к API через nginx
- **WHEN** клиент отправляет запрос на `/api/...` по HTTPS
- **THEN** ответ формирует бэкенд

### Requirement: Источник сертификатов
В dev-окружении сертификат SHALL автоматически генерироваться как самоподписанный внутри контейнера. В prod-окружении сертификат и ключ MUST предоставляться с хоста и MUST NOT храниться в репозитории.

#### Scenario: Сертификат в dev
- **WHEN** dev-окружение запускается впервые
- **THEN** самоподписанный сертификат создаётся автоматически без установки утилит на хост

#### Scenario: Ключи не в репозитории
- **WHEN** проверяется содержимое репозитория
- **THEN** приватные ключи и prod-сертификаты в нём отсутствуют и исключены через `.gitignore`

### Requirement: Защитные заголовки
nginx SHALL добавлять к ответам заголовок `Strict-Transport-Security` и `X-Content-Type-Options: nosniff`.

#### Scenario: Заголовки в ответе
- **WHEN** клиент получает ответ по HTTPS
- **THEN** в нём присутствуют перечисленные заголовки
