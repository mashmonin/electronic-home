## Purpose

Гарантирует, что вся инфраструктура (БД, веб-сервер, приложение) работает только в Docker-контейнерах и не требует установки на машину разработчика.

## ADDED Requirements

### Requirement: Единственная локальная зависимость — Docker
Разработчик SHALL мочь запустить сервис в окружении dev и prod, имея на машине только Docker. PostgreSQL, nginx, JDK и Node.js MUST NOT требоваться локально для запуска.

#### Scenario: Запуск dev-окружения одной командой
- **WHEN** разработчик выполняет документированную команду запуска dev-окружения
- **THEN** поднимаются контейнеры БД, бэкенда, фронтенда и nginx, и сервис доступен по HTTPS

#### Scenario: Остановка без следов
- **WHEN** разработчик выполняет документированную команду полной очистки окружения
- **THEN** контейнеры, сети и тома окружения удаляются, на хосте не остаётся служебных процессов

### Requirement: Отдельные окружения dev и prod
Репозиторий SHALL содержать раздельные конфигурации контейнерного окружения для `dev` и `prod`, каждое из которых запускает приложение в соответствующем профиле.

#### Scenario: Профиль соответствует окружению
- **WHEN** запущено dev-окружение
- **THEN** бэкенд работает в профиле `dev`, а в prod-окружении — в профиле `prod`

### Requirement: Сохранность данных БД
Данные PostgreSQL SHALL храниться в именованном томе и MUST переживать перезапуск и пересоздание контейнера БД.

#### Scenario: Перезапуск БД
- **WHEN** контейнер БД пересоздаётся без удаления тома
- **THEN** ранее сохранённые данные остаются доступны

### Requirement: БД недоступна извне в prod
В prod-окружении порт PostgreSQL MUST NOT публиковаться на хост; доступ к БД имеет только бэкенд через внутреннюю сеть контейнеров.

#### Scenario: Порт БД закрыт
- **WHEN** запущено prod-окружение
- **THEN** подключение к PostgreSQL с хоста извне контейнерной сети невозможно

### Requirement: Версионируемая схема БД
Изменения схемы БД SHALL применяться только через миграции, автоматически выполняемые при старте бэкенда.

#### Scenario: Миграции при старте
- **WHEN** бэкенд стартует с пустой БД
- **THEN** все миграции применяются, а журнал миграций фиксирует их выполнение
