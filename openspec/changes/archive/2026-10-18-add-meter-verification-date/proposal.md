## Why

У счётчиков воды есть срок проверки (поверки): после его истечения показания по счётчику недостоверны, и жильцу нужно об этом сообщить. Сейчас в БД, API и на экране этой даты нет.

## What Changes

- БД: у счётчика воды появляется дата проверки `verification_date` (необязательная — для счётчиков без даты статус не показывается).
- Тестовые данные (только `dev`): у «Тест 1» дата проверки 01.01.2028, у «Тест 2» — 17.10.2026 (на момент написания уже прошла, поэтому «Тест 2» демонстрирует статус «Просрочено»).
- API: в каждом элементе `meters` ответа `GET /api/accounts/{number}` появляется поле `verification_date` (дата `ГГГГ-ММ-ДД` или `null`). Сервер ничего не сравнивает и не вычисляет статус.
- Фронтенд: под полем счётчика показывается «Дата проверки: ДД.ММ.ГГГГ»; браузер сравнивает дату проверки с текущей системной датой, и если срок истёк, рядом показывается метка «Просрочено». Срок считается истёкшим со следующего дня после даты проверки: в сам день даты проверки счётчик не просрочен.
- Просрочка только информирует: ввод и отправка показаний по такому счётчику не блокируются.

### Modified Capabilities
- `water-meter-data-model`: добавляется требование о дате проверки счётчика; тестовые счётчики получают даты проверки.
- `account-info-api`: элемент `meters` получает поле `verification_date`.
- `meter-readings-screen`: добавляется требование о показе даты проверки и статуса «Просрочено».
