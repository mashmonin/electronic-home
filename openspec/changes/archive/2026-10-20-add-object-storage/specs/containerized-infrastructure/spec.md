## ADDED Requirements

### Requirement: Хранилище объектов в окружении
Docker-окружение SHALL включать сервис хранилища объектов (SeaweedFS с S3 API) и его именованный том. Данные хранилища MUST переживать перезапуск и пересоздание контейнера. Бэкенд SHALL зависеть от готовности хранилища (проверка в Compose). Образ хранилища MUST браться из публичного реестра без сборки на хосте, а ключи доступа — передаваться через переменные окружения (в prod без значений по умолчанию).

#### Scenario: Хранилище в составе окружения
- **WHEN** запускается `docker compose` для dev или prod
- **THEN** вместе с остальными сервисами поднимается хранилище, бэкенд стартует после его готовности

#### Scenario: Данные хранилища сохраняются
- **WHEN** контейнер хранилища пересоздаётся без удаления тома
- **THEN** ранее сохранённые объекты остаются доступны

#### Scenario: Нет локальной установки
- **WHEN** разработчик запускает окружение на чистой машине с одним Docker
- **THEN** никакие утилиты хранилища на хост устанавливать не нужно

### Requirement: Хранилище недоступно извне в prod
В prod-окружении порты хранилища MUST NOT публиковаться на хост; доступ имеет только бэкенд через внутреннюю сеть контейнеров. В dev порт S3 API публикуется только на `127.0.0.1`.

#### Scenario: Порт хранилища закрыт
- **WHEN** запущено prod-окружение
- **THEN** подключение к S3 API хранилища с хоста или снаружи невозможно

#### Scenario: Порт в dev только на localhost
- **WHEN** запущено dev-окружение
- **THEN** S3 API доступен на `127.0.0.1`, но не на внешнем адресе машины
