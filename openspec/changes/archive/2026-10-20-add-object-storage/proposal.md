## Why

Квитанции всех квартир сейчас лежат файлами на одном томе Docker, а в чате заявок нельзя приложить файл (фото протечки, акт, скан). Нужно собственное S3-совместимое хранилище: единое место для платёжек всех квартир и для вложений чатов, не привязанное к каталогу внутри контейнера бэкенда, с понятной сохранностью данных и без зависимости от внешних облаков.

## What Changes

- В контейнерное окружение добавляется собственное объектное хранилище **SeaweedFS** с S3 API (один контейнер, данные на именованном томе, доступно только из внутренней сети; в dev порт открыт на localhost для бэкенда из IDE). Выбран SeaweedFS (лицензия Apache 2.0, образы публикуются), потому что бесплатные образы MinIO больше не выпускаются.
- Бэкенд работает с хранилищем через S3-клиент (AWS SDK v2, path-style): два закрытых бакета — для квитанций и для вложений чатов; бакеты создаются приложением при первом обращении; ключи объектов — UUID, создаваемые сервером.
- **BREAKING**: квитанции хранятся в S3, а не в каталоге `receipts.storage.path`. Существующие файлы с тома переносятся одноразово и безопасно (идемпотентно, исходные файлы не удаляются) при старте приложения.
- В чатах заявок можно прикреплять файлы к сообщению, в том числе к первому сообщению новой заявки: до 5 файлов по 10 МБ (всего до 25 МБ), изображения (JPEG, PNG, GIF, WebP), PDF, документы Office (DOC, DOCX, XLS, XLSX) и TXT. Файл можно отправить и без текста. Скачивание только через бэкенд с проверкой прав (те же, что у переписки), без публичных и временных ссылок.
- В интерфейсе чата появляются кнопка «Прикрепить файл», список выбранных файлов с проверкой и удалением, вложения в ленте и в окне «Новая заявка»; в списке заявок превью вложения без текста: «Вложение: имя».
- Состояние хранилища входит в `/api/actuator/health`; ключи доступа в prod задаются через окружение и не имеют значений по умолчанию; наружу (через nginx) хранилище не публикуется, nginx пропускает тела запросов с вложениями.

## Capabilities

### New Capabilities
- `object-storage`: сервис SeaweedFS в Docker, бакеты, подключение и конфигурация, ключи объектов, запись и удаление, проверка состояния, закрытость от внешнего мира, перенос существующих квитанций.
- `request-attachments`: вложения сообщений заявок — форматы запросов, ограничения, типы файлов, хранение, ответы API, скачивание.

### Modified Capabilities
- `receipts`: файловое хранилище и конфигурация квитанций переходят на S3.
- `containerized-infrastructure`: сервис хранилища, его том и закрытость в prod.
- `runtime-profiles`: ключи доступа к хранилищу обязательны в prod.
- `secure-web-access`: хранилище недоступно снаружи, nginx пропускает загрузку вложений.
- `requests-api`: создание заявки и сообщения с вложениями, вложения в ответах, превью последнего сообщения.
- `requests-screen`: прикрепление файлов, вложения в ленте и в окне новой заявки.

## Impact

- Backend: зависимость `software.amazon.awssdk:s3` (+ клиент HTTP); пакет `storage` (клиент, бакеты, проверка состояния), `S3ReceiptStorage` вместо `FileSystemReceiptStorage`, перенос файлов `ReceiptFileMigration`; вложения: миграция `016` (таблица `request_attachments`), multipart-обработка в `RequestController`, скачивание; `application*.yml`; обновление `ReceiptProperties`.
- Infra: сервис `s3` и том `s3_data` в `docker-compose*.yml`, переменные `S3_ACCESS_KEY`/`S3_SECRET_KEY` в prod, лимит тела запроса nginx для `/api/requests`, том `receipts_data` монтируется в бэкенд только для переноса.
- Frontend: модуль вложений в `requests/` (выбор файлов, проверка, отправка `FormData`, отображение, скачивание через `apiFetch`), правки `ChatPanel`, `NewRequestModal`, `RequestList`.
- Тесты: интеграционные тесты бэкенда используют настоящий SeaweedFS в Testcontainers; тесты фронтенда на стабе `fetch`.
- Вне рамок: репликация и отказоустойчивость хранилища (один узел), версионирование и жизненные циклы объектов, антивирусная проверка, предпросмотр документов и миниатюры изображений, удаление и редактирование вложений, квоты на пользователя, предподписанные ссылки, веб-консоль хранилища, вложения у квитанций и в других местах.
