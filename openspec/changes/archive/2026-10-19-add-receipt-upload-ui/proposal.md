## Why

Квитанции сейчас публикуются только запросом к API с заголовком `X-Admin-Token`: администратору приходится пользоваться curl и знать общий токен. После появления входа и роли `ADMIN` публикацию можно сделать обычной операцией в интерфейсе — без общего секрета в руках человека и с понятными сообщениями об ошибках.

## What Changes

- Эндпоинт публикации `PUT /api/accounts/{number}/receipts/{month}` принимает ещё и JWT пользователя с ролью `ADMIN`; заголовок `X-Admin-Token` остаётся для скриптов и по-прежнему работает без JWT.
- В навигации администратора появляется отдельная вкладка «Выставить квитанции» с формой «Опубликовать квитанцию»: обязательный выбор квартиры, месяц, PDF-файл, необязательные суммы (капитальный ремонт и коммунальные услуги — обе или ни одной), кнопка «Опубликовать». Квартира по умолчанию не выбрана и не подставляется. Вкладка «Квитанции» остаётся только для просмотра и скачивания у собственника.
- **У администратора остаётся одна вкладка — «Выставить квитанции»**: пунктов «Показания» и «Квитанции» у него нет, шапка без данных лицевого счёта (адрес и номер счёта не показываются, `GET /api/accounts/{number}` не запрашивается). Собственник и жилец видят прежние вкладки.
- Новый эндпоинт `GET /api/accounts` (только `ADMIN`) отдаёт список лицевых счетов с адресом и номером квартиры для выбора в форме.
- Результат публикации показывается сообщением («опубликована» / «заменена» либо понятная ошибка), список квитанций обновляется сразу.
- Замена уже опубликованного месяца для выбранной квартиры требует подтверждения.
- Собственник и жилец вкладки загрузки не видят; сервер отказывает им в публикации (`403`) независимо от интерфейса.
- **BREAKING** (для спеки, не для клиентов): требование «Публикации в интерфейсе нет» удаляется — оно прямо запрещало загрузку на вкладке.

### Modified Capabilities
- `meter-readings-screen`: экран администратора без данных лицевого счёта, загрузка счёта только для собственника и жильца, меню профиля администратора.
- `login-screen`: пункты навигации по ролям.
- `receipts`: публикация доступна `ADMIN` по JWT и по `X-Admin-Token`; вкладка «Выставить квитанции» с формой и обязательным выбором квартиры, список квартир `GET /api/accounts`, навигация по ролям (у администратора только «Выставить квитанции»); удалено требование об отсутствии публикации в интерфейсе.
- `authorization`: в матрицу полномочий добавлены публикация квитанций и список всех лицевых счетов (только `ADMIN`).
- `authentication`: уточнение защиты публикации — она открыта для запросов с `X-Admin-Token` и для администратора с JWT.

## Impact

- Backend: новый `GET /api/accounts` (администратор, список счетов с адресом); `ReceiptController`/`ReceiptService` — решение о праве публикации принимается по роли `ADMIN` из аутентификации либо по токену; `SecurityConfig` не меняется (маршрут и так открыт, JWT, если он передан, проверяется).
- Frontend: вкладка «Выставить квитанции» с формой (antd `Select`, `DatePicker`, `Upload`, `InputNumber`, `Popconfirm`), навигация по ролям, шапка администратора без счёта, функции `publishReceipt` и `fetchAccounts`, тесты.
- Тесты: `ReceiptsApiIT`/`AccessControlIT` дополняются сценариями публикации от лица `ADMIN`, `OWNER`, `RESIDENT`.
- Вне рамок: удаление квитанций, серверный поиск и пагинация списка квартир, пакетная загрузка, автоматический разбор сумм из PDF, отказ от `X-Admin-Token`.
