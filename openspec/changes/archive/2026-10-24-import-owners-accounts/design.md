## Context

Таблицы уже есть: `addresses` (квартиры 1–138 «ул. Тестовая, Дом» из миграции 020), `owners`, `accounts` (`number` varchar(32), у тестового счёта 12 знаков `000000000001`), `address_owners`, `account_owners`, `users` (BCrypt, `uq_users_login_lower`), `user_accounts`. В `prod` пользователей нет, вход создаётся вручную. Liquibase запускается с контекстами `dev` / `prod`; каталог `data/` в `.gitignore`. Мотивация — см. proposal.md.

Проверка файла `сентябрь_2026.xls` (один лист, 142 л/с, каждая квитанция повторена дважды): паспортов, СНИЛС, e-mail, дат рождения и личных телефонов нет; есть ФИО и суммы долга/оплат собственников, а реквизиты и телефон ТСЖ публичные. Состав: 138 квартир (л/с совпадает с номером квартиры), 4 офиса; 3 организации (л/с 117 в квартире 117, офисы 003 и 004); 137 физических лиц на квартирах, 128 уникальных ФИО, 8 человек с несколькими счетами (совпавшие логины — всегда один и тот же человек).

## Goals / Non-Goals

**Goals:**
- Воспроизводимо подготовить данные из файла и применить их миграцией Liquibase.
- Не хранить в git ФИО, логины, пароли и хеши.

**Non-Goals:**
- Организации и офисы (отложены), реальный адрес дома, принудительная смена пароля, рассылка паролей, интерфейс администратора для паролей.

## Decisions

1. **Генератор — скрипт в репозитории (`tools/owners-import/`, Python + `xlrd`, `bcrypt`)**. Читает xls, проверяет файл на чувствительные данные (регулярные выражения: e-mail, телефоны, СНИЛС, паспорт, дата рождения; значения не печатает), берёт только л/с, ФИО и «Кв.», убирает дубликаты квитанций, формирует `data/migrations/021-import-owners.sql` и `data/credentials/owner-passwords.csv` (логин;пароль;л/с), печатает отчёт без ПДн (число записей, пропущенные л/с). Альтернатива — Java-код при старте: тянет ПДн и xls в приложение.
2. **Changeset в git ссылается на SQL-файл из `data/`**, контекст `owners-import`: `021-import-owners.yaml` с `sqlFile`, путь через параметр (`${owners.import.file}`), `context: owners-import`. Для разового развёртывания включается `SPRING_LIQUIBASE_CONTEXTS=prod,owners-import` и монтируется каталог с файлом в контейнер backend (только чтение). Без контекста changeset пропускается, проект и тесты не зависят от `data/`. Альтернатива — класть SQL в classpath: ПДн в git, отвергнуто.
3. **SQL идемпотентный**, как в 020: `INSERT … SELECT … WHERE NOT EXISTS`/`ON CONFLICT DO NOTHING`; квартира ищется по `('ул. Тестовая','Дом', N)`; если квартиры нет — явная ошибка (`DO $$ … RAISE EXCEPTION`), транзакция откатывается целиком. Номер счёта = номер л/с с нулями слева до 12 знаков (формат существующих счетов); поиск по `accounts.number`.
4. **Логин и транслитерация** — таблица в скрипте по маске пользователя (первая буква имени + первая буква отчества + фамилия, строчные); `ё→e`, `й→y`, `ы→y`, `х→kh`, `ц→ts`, `ч→ch`, `ш→sh`, `щ→shch`, `ж→zh`, `ю→yu`, `я→ya`, `ъ`/`ь` опускаются. Одно ФИО ⇒ один пользователь на все его счета; одинаковый логин при разных ФИО — остановка. Существующий логин: `ON CONFLICT DO NOTHING` по `lower(login)`, пароль существующего не меняется.
5. **Транспортный пароль**: 12 знаков из алфавита без похожих символов (`secrets`), BCrypt cost 10 (`$2a$`, как в 010). Открытый пароль только в CSV; CSV создаётся с правами 600 и не логируется. Выданные пароли после передачи собственникам рекомендуется удалить файл.
6. **Пропуски**: организация — по признакам в поле плательщика (`ООО`, `ПАО`, `ОАО`, `АО`, кавычки/«банк» и ФИО не из трёх слов), офис — по «Оф.» в адресе; список пропущенных л/с в отчёте.

## Risks / Trade-offs

- [`sqlFile` с путём вне classpath может не открыться в Liquibase под Spring] → проверить на этапе реализации (`file:` путь + том); запасной вариант — применять сгенерированный SQL через `psql` и `databasechangelog` не трогать, описано в README.
- [Определение организаций по тексту может ошибиться] → отчёт с пропущенными л/с проверяется человеком до применения; ФИО не из трёх слов останавливают подготовку.
- [Совпадение ФИО разных людей приравняет их к одному] → допущение: одинаковое полное ФИО — один человек; отражено в отчёте (список слитых л/с).
- [Открытые пароли в файле] → `data/` в `.gitignore`, права 600, удалить после выдачи; в БД и в git только хеши/ничего.
- [Транспортный пароль без принудительной смены] → собственник меняет его сам, если появится такая функция; вне объёма.
- [Откат] → rollback удаляет созданные записи по маркеру номера счетов/логинов из файла; на `prod` предпочтительнее восстановление из бэкапа БД до миграции.
