## Why

Сервису нужна основа данных: кто и где живёт, на какие лицевые счета передаются показания. Сейчас БД пуста (`db.changelog-master.yaml` без изменений), а экран ввода показаний работает на заглушке с адресами и лицевыми счетами. Без модели данных нельзя сделать ни API, ни авторизацию жильцов.

## What Changes

- Новые таблицы БД через Liquibase: адреса (адрес = квартира), лицевые счета, собственники.
- Связи «многие ко многим» через две связующие таблицы: собственники ↔ адреса (у адреса несколько собственников, у собственника несколько адресов) и собственники ↔ лицевые счета (у счёта несколько совладельцев).
- Связь «один ко многим»: у одного адреса несколько лицевых счетов, у счёта ровно один адрес.
- Ограничения целостности: уникальность адреса и номера лицевого счёта, внешние ключи, запрет дублей в связках.
- Поля сознательно минимальные: только то, что идентифицирует запись (адрес — улица, дом, квартира; счёт — номер; собственник — ФИО). Доли собственности, даты владения, контакты и документы не входят.
- JPA-сущности, REST API и перевод фронтенда с заглушки на реальные данные в это изменение не входят.

(нет)

## Impact

- `backend/src/main/resources/db/changelog/`: новый changelog с таблицами, подключение в `db.changelog-master.yaml`.
- `backend/src/test/`: интеграционный тест миграции на PostgreSQL (Testcontainers).
- Новых зависимостей нет (Liquibase, PostgreSQL и Testcontainers уже подключены).
- Frontend, nginx, Docker-инфраструктура не затрагиваются. Миграция применяется при старте приложения в профилях `dev` и `prod`.
