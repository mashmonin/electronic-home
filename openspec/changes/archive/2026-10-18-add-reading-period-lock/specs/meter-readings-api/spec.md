## ADDED Requirements

### Requirement: Период передачи показаний
Система SHALL делить время на подряд идущие периоды передачи: период начинается 26-го числа месяца и заканчивается 25-м числом следующего месяца включительно (день закрытия, 25, задаётся конфигурацией `readings.period.closing-day`). Период SHALL называться по месяцу, в котором он заканчивается. Текущий период MUST определяться по текущей дате сервера (только календарная дата); каждая дата принадлежит ровно одному периоду.

#### Scenario: Середина периода
- **WHEN** текущая дата сервера — 18 октября 2026
- **THEN** текущий период — с 26 сентября по 25 октября 2026 («октябрь»), следующий начинается 26 октября

#### Scenario: Последний день периода
- **WHEN** текущая дата сервера — 25 октября 2026
- **THEN** текущий период по-прежнему «октябрь» (с 26 сентября по 25 октября)

#### Scenario: Первый день нового периода
- **WHEN** текущая дата сервера — 26 октября 2026
- **THEN** текущий период — с 26 октября по 25 ноября 2026 («ноябрь»)

#### Scenario: Переход через границу года
- **WHEN** текущая дата сервера — 28 декабря 2026
- **THEN** текущий период — с 26 декабря 2026 по 25 января 2027 («январь»)

### Requirement: Повторная подача за период
Если по счётчику уже есть показание, дата которого входит в текущий период, сохранение нового показания по этому счётчику SHALL быть отклонено ответом `400` с кодом `ALREADY_SUBMITTED` для этого счётчика (в дополнение к кодам требования «Проверка запроса»). Ошибка SHALL перечисляться в общем списке `errors`, а при любой ошибке в запросе ничего не сохраняется. Показание, сданное в прошлом периоде, повторной подачей не считается.

#### Scenario: Повторная подача в том же периоде
- **WHEN** по счётчику «Тест 1» уже есть показание от 18 октября, а 20 октября клиент отправляет новое
- **THEN** ответ `400`, в `errors` для «Тест 1» код `ALREADY_SUBMITTED`, ничего не сохранено

#### Scenario: Подача в новом периоде
- **WHEN** последнее показание счётчика сдано 25 октября, а 26 октября клиент отправляет новое
- **THEN** показание сохраняется

#### Scenario: Показание прошлого периода
- **WHEN** последнее показание счётчика сдано 25 сентября, а 18 октября клиент отправляет новое
- **THEN** показание сохраняется, так как 25 сентября относится к периоду «сентябрь»

#### Scenario: Несколько счётчиков, один уже сдан
- **WHEN** клиент отправляет показания для «Тест 1» (уже сдан в этом периоде) и «Тест 2» (не сдан)
- **THEN** ответ `400` с `ALREADY_SUBMITTED` для «Тест 1», показание «Тест 2» не сохранено

### Requirement: Параметр отключения проверки периода
Бэкенд SHALL поддерживать параметр конфигурации `readings.period.enforced`. При значении `true` (по умолчанию) требование «Повторная подача за период» MUST выполняться. При значении `false` повторная подача за период MUST быть разрешена, а проверка остальных правил записи сохраняется. Значение по умолчанию `true` MUST действовать во всех профилях, включая `dev`; для тестирования проверку выключают явно, в том числе переменной окружения (`READINGS_PERIOD_ENFORCED=false`).

#### Scenario: Проверка включена
- **WHEN** параметр равен `true`, а по счётчику уже есть показание в текущем периоде
- **THEN** новое показание отклоняется с кодом `ALREADY_SUBMITTED`

#### Scenario: Проверка выключена
- **WHEN** параметр равен `false`, а по счётчику уже есть показание в текущем периоде
- **THEN** новое показание сохраняется, если оно проходит остальные проверки

#### Scenario: Параметр не задан
- **WHEN** параметр не задан ни в одном из профилей, в том числе `dev`
- **THEN** проверка включена

#### Scenario: Выключение для тестирования
- **WHEN** приложение запущено с переменной окружения `READINGS_PERIOD_ENFORCED=false`
- **THEN** проверка выключена
