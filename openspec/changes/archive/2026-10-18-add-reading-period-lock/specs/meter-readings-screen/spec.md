## ADDED Requirements

### Requirement: Подпись периода и статус сдачи
Над карточками счётчиков экран SHALL показывать подпись «Показания за <месяц>», где месяц — название месяца, в котором заканчивается текущий период передачи из ответа API (`reading_period.end`), в именительном падеже. Под подписью экран SHALL показывать строку статуса:
- если по всем счётчикам есть показания за период (`reading_period.all_submitted`): «Показания сданы, новые можно будет отправить после <день> <месяц>», где дата — последний день периода (`reading_period.end`) с месяцем в родительном падеже;
- если часть счётчиков сдана: «Часть показаний сдана. Передайте остальные до <день> <месяц>»;
- если ничего не сдано: «Передайте показания до <день> <месяц>».

Подпись SHALL быть заголовком страницы: крупный жирный шрифт (26px), выравнивание по левому краю; строка статуса SHALL идти под ней полужирным шрифтом 15px и тоже по левому краю. Экран MUST NOT сравнивать даты сам: период и статус берутся только из ответа API.

#### Scenario: Оформление и выравнивание
- **WHEN** экран открыт с любым набором счётчиков
- **THEN** «Показания за <месяц>» показано крупным жирным шрифтом (26px), строка статуса — под ним полужирным шрифтом 15px, обе строки выровнены по левому краю, по центру страницы ничего из них нет

#### Scenario: Показания ещё не сданы
- **WHEN** API вернул период с 26 сентября по 25 октября 2026 и ни один счётчик не сдан
- **THEN** показаны «Показания за октябрь» и «Передайте показания до 25 октября»

#### Scenario: Показания сданы
- **WHEN** API вернул `all_submitted` истина для периода, заканчивающегося 25 октября
- **THEN** показаны «Показания за октябрь» и «Показания сданы, новые можно будет отправить после 25 октября»

#### Scenario: Сдана часть показаний
- **WHEN** показание есть только у одного из двух счётчиков
- **THEN** показаны «Показания за октябрь» и «Часть показаний сдана. Передайте остальные до 25 октября»

#### Scenario: Первая подача после установки
- **WHEN** пользователь впервые открывает приложение, и за текущий период показаний нет
- **THEN** экран показывает подпись текущего месяца-периода и редактируемую форму

#### Scenario: Новый период
- **WHEN** пользователь открывает приложение 26 октября после сдачи показаний 18 октября
- **THEN** API вернул период «ноябрь», поля снова доступны, подпись «Показания за ноябрь», в «Предыдущее показание» стоят значения, сданные 18 октября

#### Scenario: Пропущенный период
- **WHEN** за прошлый период показания не сдавались, а сейчас идёт следующий
- **THEN** форма относится только к текущему периоду, подпись — месяц текущего периода

### Requirement: Сданные показания не редактируются
Если API вернул у счётчика `input_locked` истина, его карточка SHALL показывать показание за текущий период (`current_period_reading.value` с тремя знаками после запятой) в недоступном для правки поле, а «Предыдущее показание» — значение, предшествовавшее сданному (`current_period_reading.previous`), либо прочерк, если его нет. Такой счётчик MUST NOT попадать в запрос на сохранение. Когда заблокированы все счётчики, кнопки «Отправить показания» и «Сбросить форму» MUST оставаться на экране, но быть недоступными (disabled); если заблокирована только часть, остальные карточки и кнопки остаются доступными. После успешного сохранения экран SHALL перезапрашивать данные и показывать сданные значения заблокированными.

#### Scenario: Карточка со сданным показанием
- **WHEN** по «Тест 1» за текущий период сдано `250.125` (предыдущее `245.300`) и `input_locked` истина
- **THEN** в карточке «Тест 1» недоступное поле содержит `250.125`, строка «Предыдущее показание: 245.300 м³»

#### Scenario: Все показания сданы
- **WHEN** у обоих счётчиков `input_locked` истина
- **THEN** кнопки «Отправить показания» и «Сбросить форму» показаны, но недоступны, все поля недоступны и содержат сданные значения

#### Scenario: Сдана часть счётчиков
- **WHEN** `input_locked` истина только у «Тест 1»
- **THEN** поле «Тест 1» недоступно, поле «Тест 2» редактируемо, кнопки показаны, в запрос попадёт только «Тест 2»

#### Scenario: После отправки
- **WHEN** пользователь отправил показания и API сохранил их
- **THEN** форма остаётся на экране, поля с отправленными значениями недоступны, подпись «Показания сданы, новые можно будет отправить после 25 октября»

#### Scenario: Сервер отклонил повторную подачу
- **WHEN** API отвечает ошибкой `ALREADY_SUBMITTED` для счётчика
- **THEN** отображается предупреждение «Показания за этот период уже сданы», данные счёта перезапрашиваются, и карточка этого счётчика показывает сданное значение заблокированным

#### Scenario: Проверка отключена
- **WHEN** API вернул `input_locked` ложь у счётчика, по которому есть показание за период
- **THEN** поле редактируемо и пусто, повторная отправка возможна

### Requirement: Пометка тестового режима
Если API вернул `reading_period.enforced` ложь, экран SHALL показывать над карточками пометку «Тестовый режим: ограничение периода передачи отключено». При истинном значении пометки быть не должно.

#### Scenario: Проверка отключена на сервере
- **WHEN** API вернул `enforced` ложь
- **THEN** над карточками видна пометка «Тестовый режим: ограничение периода передачи отключено»

#### Scenario: Проверка включена на сервере
- **WHEN** API вернул `enforced` истина
- **THEN** пометки тестового режима нет

## MODIFIED Requirements

### Requirement: Заголовок периода
Экран MUST NOT показывать заголовок «Ввод показаний». Заголовком страницы SHALL быть подпись периода «Показания за <месяц>» по требованию «Подпись периода и статус сдачи», выровненная по левому краю.

#### Scenario: Отображение периода
- **WHEN** пользователь открывает экран
- **THEN** вверху слева отображается заголовок «Показания за <месяц>», а заголовка «Ввод показаний» и прежней строки вида «Август 2026 · Передайте показания до 25 числа» нет
