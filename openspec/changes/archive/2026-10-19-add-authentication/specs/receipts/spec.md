## ADDED Requirements

### Requirement: Квитанции только по токену и роли
Эндпоинты `GET /api/accounts/{number}/receipts` и `GET /api/accounts/{number}/receipts/{month}` SHALL требовать аутентификации и доступа к счёту по правилам спецификации `authorization`: без токена — `401`; жилец (`RESIDENT`) и любой пользователь без доступа к счёту — `403`. Доступ к квитанциям имеют `ADMIN` (любой счёт) и `OWNER` (свои счета). Публикация `PUT /api/accounts/{number}/receipts/{month}` по-прежнему защищена только заголовком `X-Admin-Token` и JWT не требует.

#### Scenario: Без токена
- **WHEN** клиент запрашивает список квитанций без токена
- **THEN** ответ `401`

#### Scenario: Собственник скачивает свою квитанцию
- **WHEN** собственник счёта скачивает опубликованную квитанцию этого счёта
- **THEN** ответ `200` с PDF

#### Scenario: Жилец
- **WHEN** жилец запрашивает список или файл квитанции своего счёта
- **THEN** ответ `403`

#### Scenario: Публикация по административному токену
- **WHEN** скрипт публикует квитанцию с верным `X-Admin-Token` и без JWT
- **THEN** публикация проходит так же, как до введения аутентификации
