## Why

Жильцам нужны квитанции на оплату по месяцам, а управляющей компании — способ их опубликовать. Сейчас в системе нет ни таблицы квитанций, ни места для PDF-файлов. Этим изменением закладывается основа: таблица, хранилище файлов на томе Docker, загрузка и скачивание через API, а также вкладка «Квитанции» на фронтенде, где жилец видит квитанции по месяцам и скачивает их.

## What Changes

- **Таблица `receipts`** (миграция Liquibase): квитанция принадлежит лицевому счёту и месяцу (`YYYY-MM`); на счёт и месяц — не более одной квитанции. Хранятся ключ файла, размер, SHA-256, дата публикации и признак `is_test`. Сами файлы в БД не лежат.
- **Хранилище файлов** за интерфейсом `ReceiptStorage`; реализация — каталог на томе (`receipts.storage.path`). Файл получает случайное имя-ключ (UUID), запись атомарна (временный файл → перемещение), при сбое БД «осиротевших» файлов не остаётся, при замене старый файл удаляется после успешного сохранения. В `docker-compose.yml` добавляется именованный том для бэкенда.
- **API:**
  - `PUT /api/accounts/{number}/receipts/{month}` — публикация (тело — PDF как `application/pdf`; повторный вызов для того же месяца заменяет файл). Защищена токеном администратора в заголовке `X-Admin-Token` (`receipts.admin-token`); без настроенного токена загрузка отключена.
  - `GET /api/accounts/{number}/receipts` — список опубликованных квитанций (месяц, размер, дата публикации), новые первыми.
  - `GET /api/accounts/{number}/receipts/{month}` — скачивание PDF.
  - Проверки: файл начинается с `%PDF-`, размер не больше `receipts.max-size` (по умолчанию 5 МБ), формат месяца, существование счёта.
- **Инфраструктура:** образ бэкенда создаёт каталог тома с правами пользователя `app`; nginx разрешает тело запроса до 6 МБ для `/api/` (по умолчанию 1 МБ).
- Чтение квитанций открыто так же, как остальной API (по номеру счёта, без авторизации) — **это риск**: квитанции содержат персональные данные; авторизация обязательна до публикации реальных квитанций (см. design.md).
- **Суммы квитанции.** У квитанции появляются необязательные суммы — капитальный ремонт и коммунальные услуги — с источником (`MANUAL` сейчас, `PARSED` зарезервирован) и временем записи (миграция `008`). Пока PDF не разбирается автоматически, суммы передаются при публикации параметрами `capital_repair` и `utilities`; списки и ответы публикации содержат `capital_repair_amount` и `utilities_amount`. **Автоматический разбор PDF при загрузке — отдельное будущее изменение**: схема под него уже готова. Для тестовой квитанции (`Я-Конфигуратор.pdf`, октябрь 2026) придуманы суммы: капремонт 1842,50 ₽, коммунальные услуги 6318,27 ₽.
- **Фронтенд.** В шапке появляется пункт навигации «Квитанции» (рядом с «Показания»). Вкладка показывает квитанции текущего лицевого счёта по месяцам, новые первыми, компонентом-аккордеоном: заголовок панели «Октябрь 2026», внутри две суммы («Капитальный ремонт» и «Коммунальные услуги») и ссылка «Скачать PDF». Размер файла и дата публикации не показываются. Есть состояния загрузки, пустого списка и ошибки. Активная вкладка хранится в адресе (`?tab=receipts`), `?account=` сохраняется. Роутер и новые зависимости не нужны, счёт и шапка общие для обеих вкладок.
- Интерфейс администратора (публикация квитанций из браузера) не входит в изменение: публикуют через API с токеном.

## Capabilities

### New Capabilities
- `receipts`: хранение, публикация, список и скачивание PDF-квитанций по лицевому счёту и месяцу, а также вкладка «Квитанции» на экране.

### Modified Capabilities
- `meter-readings-screen`: навигация в шапке получает пункт «Квитанции» и выделение активной вкладки (требование «Шапка экрана с данными лицевого счёта»).
