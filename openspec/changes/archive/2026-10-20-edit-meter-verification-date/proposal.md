## Why

Срок проверки счётчика (`water_meters.verification_date`) сейчас задаётся только миграциями и не может быть изменён из приложения. После очередной поверки собственник или администратор должен обновить срок, подтвердив это актом проверки, и этот акт должен сохраняться.

## What Changes

- Эндпоинт загрузки акта: `POST /api/accounts/{number}/meters/{meterNumber}/verification-act-uploads` принимает файл, кладёт его в S3 и возвращает «ссылку» — ключ объекта (адресов хранилища и предподписанных ссылок система по-прежнему не выдаёт). Не использованная загрузка удаляется фоновой очисткой через 24 часа.
- Эндпоинт изменения срока: `PUT /api/accounts/{number}/meters/{meterNumber}/verification-date` с новой датой и ключом акта; акт обязателен.
- **Изменение собственником не применяется сразу**: создаётся акт-черновик (`is_draft = true`, дата хранится в нём) и заявка-чат на администратора вида `VERIFICATION` с номером `П-ддммгг-NNNN`. Первое сообщение: «Добрый день! Выполнил проверку счетчика №{номер счётчика из БД}», вложение — акт (копируется в бакет вложений; фото отображается как фото). Черновики клиенту не возвращаются, карточка сохраняет прежнюю дату.
- Подтверждение: кнопка «Подтвердить» у администратора = перевод заявки `ACCEPTED → IN_PROGRESS`. В той же транзакции с черновика снимается метка, предыдущий действующий акт мягко удаляется (`is_archive = true`, объект остаётся), новый действует (`is_archive = false`), `water_meters.verification_date` обновляется. Если срок меняет администратор, заявка не создаётся и изменение применяется сразу.
- **Статусная модель заявок для всех заявок** (Enum: `ACCEPTED` «Принята», `IN_PROGRESS` «В работе», `DONE` «Выполнена», `CLOSED` «Закрыта»): новая заявка — «Принята»; администратор по шагам: «Взять в работу» (у `П` — «Подтвердить») → «Выполнено» → «Закрыть», шаг только вперёд, `PUT /api/requests/{id}/status`. В закрытую заявку писать нельзя. **BREAKING**: ранее статус был удалён (миграция `015`) и «закрывать заявки нельзя» — теперь статус возвращается и спека меняется; старые заявки при миграции получают «Принята».
- Заявки получают вид (`GENERAL`/`VERIFICATION`); номер вида `О-…` для обычных и `П-…` для заявок о проверке, сквозной счётчик общий.
- Акты — новая таблица `meter_verification_acts` (с `is_draft`, `is_archive`), бакет актов `electronic-home-meter-acts` (`S3_METER_ACTS_BUCKET`).
- Экран счётчиков: кнопка «Изменить» у даты проверки открывает окно с датой и обязательной загрузкой акта (при прикреплении файл сразу грузится в хранилище). После сохранения собственником — уведомление с номером заявки, дата прежняя; администратором — дата меняется сразу.
- Экран заявок: метка статуса, кнопки перехода у администратора, блокировка ввода в закрытой заявке.
- Права: менять срок могут администратор и собственник своего счёта; менять статус заявок — только администратор.

## Capabilities

### New Capabilities
- `meter-verification`: изменение срока проверки счётчика с актом проверки — эндпоинты загрузки акта и изменения даты, проверка файла и даты, хранение актов, мягкое удаление предыдущего акта (`is_archive`), очистка неиспользованных загрузок.

### Modified Capabilities
- `meter-readings-screen`: редактирование даты проверки в карточке, окно с актом, поведение после сохранения.
- `authorization`: полномочия на загрузку акта, изменение срока и смену статуса заявок.
- `object-storage`: третий бакет — для актов проверки счётчиков.
- `requests-api`: статус и вид заявки, номер с буквой `П`, список с `kind`/`status`, смена статуса, запрет сообщений в закрытой заявке, заявка о проверке счётчика.
- `requests-screen`: метка статуса, кнопки администратора, закрытая заявка.
- `request-attachments`: акт проверки как вложение первого сообщения заявки о проверке.

## Impact

- Backend: миграции `017` (таблицы `meter_verification_acts` с `is_draft`/`is_archive` и `meter_act_uploads`) и `018` (колонки `kind`, `status` у `requests` со значениями по умолчанию для старых заявок); пакеты `account`/новый `meter` и `request` (`RequestStatus`, смена статуса, создание заявки `VERIFICATION` из сервиса счётчиков, `RequestNumbers` с буквой вида), копирование акта в бакет вложений, `@Scheduled`-очистка, `StorageProperties`/`application*.yml`, общая проверка файла по сигнатуре выносится из `request.AttachmentTypes`.
- Infra: переменная `S3_METER_ACTS_BUCKET` в `docker-compose*.yml`; лимит тела nginx для `/api/` проверить.
- Frontend: окно изменения срока, кнопка в `MeterCard`, API-клиент, уведомление; статус, кнопки и блокировка в `ChatPanel`/`RequestList`, типы заявок.
- Тесты: интеграционные на SeaweedFS в Testcontainers (загрузка, черновик, заявка `П`, подтверждение, архивация, статусы, права) и тесты фронтенда на стабе `fetch`; обновить существующие тесты заявок под `kind`/`status`.
- Вне рамок: просмотр и скачивание актов вне чата, история актов в интерфейсе, откат статуса назад, отклонение заявки о проверке (черновик без подтверждения остаётся навсегда), уведомления по почте, поиск по номеру с латинской «P» как «П», физическое удаление архивных объектов.
