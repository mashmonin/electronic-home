## MODIFIED Requirements

### Requirement: Бакеты
Система SHALL использовать четыре бакета: для квитанций (по умолчанию `electronic-home-receipts`), для вложений чатов (по умолчанию `electronic-home-attachments`), для актов проверки счётчиков (по умолчанию `electronic-home-meter-acts`, переменная окружения `S3_METER_ACTS_BUCKET`, параметр `storage.s3.meter-acts-bucket`) и для загруженных ведомостей начислений (по умолчанию `electronic-home-statements`, переменная окружения `S3_STATEMENTS_BUCKET`, параметр `storage.s3.statements-bucket`). Названия переопределяются конфигурацией. Если бакета нет, приложение MUST создать его при первом обращении к нему (создание идемпотентно и безопасно при одновременных запросах); отсутствие бакета при старте приложения не должно мешать запуску.

#### Scenario: Первый запуск
- **WHEN** хранилище пусто и публикуется первая квитанция
- **THEN** бакет квитанций создаётся автоматически и квитанция сохраняется

#### Scenario: Бакеты уже есть
- **WHEN** приложение запускается при существующих бакетах
- **THEN** они используются, ошибок и повторного создания нет

#### Scenario: Хранилище недоступно при старте
- **WHEN** приложение стартует, а хранилище ещё не отвечает
- **THEN** приложение запускается, а операции с файлами завершаются ошибкой, пока хранилище недоступно

#### Scenario: Бакет актов создаётся при первой загрузке
- **WHEN** бакета актов нет и загружается первый акт проверки
- **THEN** бакет создаётся автоматически, акт сохраняется

#### Scenario: Бакет ведомостей создаётся при первой загрузке
- **WHEN** бакета ведомостей нет и администратор загружает первую ведомость
- **THEN** бакет создаётся автоматически, ведомость сохраняется, она недоступна анонимно
