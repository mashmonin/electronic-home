## Why

Сейчас администратор выставляет квитанции по одной: выбирает квартиру, месяц, PDF и суммы вручную, а 138 квартир требуют 138 таких операций. Бухгалтерия уже выгружает единую ведомость начислений (`сентябрь_2026.xls`, по две квитанции на лицевой счёт: «Жилищно-коммунальные услуги» и «Капитальный ремонт»), из которой квитанции можно собрать автоматически.

## What Changes

- Во вкладке администратора «Выставить квитанции» появляется карточка «Загрузить ведомость»: администратор выбирает `.xls` файл с такой же структурой, как у выгрузки за сентябрь 2026.
- Файл сразу сохраняется в закрытом S3 (новый бакет ведомостей), создаётся пакет (batch), запрос возвращается без ожидания, а формирование идёт в фоне.
- Для каждого лицевого счёта сервис находит в ведомости обе квитанции, формирует один PDF (по образцу формы: разделы 1–4 для «Жилищно-коммунальных услуг» и «Капитального ремонта»), сохраняет его в бакет квитанций и публикует как квитанцию счёта за расчётный месяц из ведомости; суммы «капремонт» и «коммунальные» заполняются автоматически (источник `PARSED`).
- Собственники видят новые PDF на своей вкладке «Квитанции» без изменений в их интерфейсе: используется существующая публикация, список и скачивание.
- Администратор видит ход и итог пакета: сколько счетов обработано, создано, заменено, пропущено, с ошибкой; список пропущенных счетов (нет такого счёта в базе, организация, офис) и причины. Прошлые пакеты видны в списке.
- Повторная загрузка за тот же месяц заменяет ранее созданные квитанции (с их суммами).

## Capabilities

### New Capabilities

- `receipt-batch-generation`: загрузка ведомости начислений, фоновое формирование PDF-квитанций по счетам, публикация собственникам, отчёт о пакете.

### Modified Capabilities

- `object-storage`: четвёртый бакет — для загруженных ведомостей (по умолчанию `electronic-home-statements`).

## Impact

- Backend: разбор `.xls` (Apache POI), генерация PDF с кириллицей (OpenPDF + встроенный шрифт), фоновая обработка, таблицы пакетов и их позиций (Liquibase), эндпоинты `/api/receipt-batches` только для `ADMIN`, использование существующего `ReceiptService`.
- Frontend: карточка загрузки ведомости, прогресс и итог пакета, список пакетов во вкладке «Выставить квитанции».
- Конфигурация: бакет ведомостей, лимит размера файла.
- Ведомость содержит ФИО, долги и оплаты всех собственников: она хранится только в закрытом бакете, доступна только администратору и не попадает в журналы.
