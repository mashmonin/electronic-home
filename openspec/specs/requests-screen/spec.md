## Purpose

Описывает вкладку «Заявки»: список слева и чат справа, поиск по номеру, выделение заявок без ответа, создание заявки, отправку сообщений, автообновление и адаптивную вёрстку.

## Requirements

### Requirement: Вкладка «Заявки»
Собственнику и администратору навигация шапки SHALL содержать активный пункт «Заявки»: клик по нему открывает вкладку заявок, адрес получает `tab=requests`, пункт выделяется основным цветом. У собственника пункт идёт после «Квитанции», у администратора — после «Выставить квитанции». Жильцу пункта нет, а адрес с `tab=requests` открывает показания. Выбранная заявка отражается в адресе параметром `request` (идентификатор); открытие адреса с `tab=requests&request=<id>` сразу показывает эту заявку и сохраняется при обновлении страницы. Если заявка недоступна, показывается пустой чат с подсказкой «Выберите заявку», а параметр игнорируется.

#### Scenario: Переход к заявкам
- **WHEN** собственник нажимает «Заявки» в шапке
- **THEN** открывается вкладка заявок, адрес содержит `tab=requests`, пункт «Заявки» выделен

#### Scenario: Прямая ссылка на заявку
- **WHEN** собственник открывает `/?tab=requests&request=12`, а заявка 12 его
- **THEN** сразу показана вкладка заявок, заявка 12 выделена в списке, справа её чат

#### Scenario: Чужая заявка в адресе
- **WHEN** адрес указывает заявку, которой нет у пользователя
- **THEN** справа «Выберите заявку», ошибки нет

#### Scenario: Жилец
- **WHEN** жилец открывает адрес с `tab=requests`
- **THEN** открыты показания, пункта «Заявки» в навигации нет

### Requirement: Панель заявок
Над панелями, сразу под шапкой сайта, SHALL быть заголовок «Заявки» (тот же стиль, что у заголовков других вкладок, выровнен по левому краю), а у собственника справа в той же строке — кнопка «Новая заявка». Ниже вкладка SHALL состоять из двух панелей: слева список заявок, справа чат выбранной заявки. Список загружается из `GET /api/requests`; элемент показывает номер заявки, начало последнего сообщения и его время, а для администратора — ещё «кв. N · логин автора». Список показывается в порядке ответа API (сначала заявки без ответа, самые давно ожидающие выше, затем остальные), выбранная заявка выделена. Над списком SHALL быть поле поиска по номеру (см. требование «Поиск по номеру»). Статусов, фильтра по статусу и закрытия заявок нет. Пока список загружается, показывается индикатор; пустой список — сообщение «Заявок пока нет» (у собственника с подсказкой создать первую); ошибка — «Не удалось загрузить заявки» с кнопкой «Повторить».

#### Scenario: Список собственника
- **WHEN** у собственника три заявки
- **THEN** слева три элемента в порядке ответа API, чат справа пуст с подсказкой «Выберите заявку»

#### Scenario: Список администратора
- **WHEN** администратор открывает вкладку
- **THEN** слева заявки всех собственников, в каждом элементе видны квартира и логин автора

#### Scenario: Нет статусов
- **WHEN** открыта вкладка заявок
- **THEN** в списке и в шапке чата нет статусов «Открыта» и «Закрыта», нет переключателя «Все / Открытые / Закрытые» и кнопок «Закрыть заявку» и «Открыть снова»

#### Scenario: Пустой список
- **WHEN** у собственника нет заявок
- **THEN** слева «Заявок пока нет», а над панелями кнопка «Новая заявка»

#### Scenario: Ошибка загрузки
- **WHEN** запрос списка завершается ошибкой
- **THEN** показано «Не удалось загрузить заявки» и кнопка «Повторить»

### Requirement: Поиск по номеру
Над списком заявок SHALL быть поле поиска с подсказкой «Поиск по номеру заявки» и кнопкой очистки. Ввод фрагмента номера (в любом месте номера, без учёта регистра, латинская `O` равна кириллической `О`) отправляет запрос `GET /api/requests?q=<фрагмент>` с задержкой около 300 мс после последнего нажатия, чтобы не посылать запрос на каждую букву; список заменяется найденными заявками в том же порядке. Если ничего не найдено, показывается «Ничего не найдено по запросу «<фрагмент>»». Очистка поля возвращает полный список. Пока введён фрагмент, фоновое обновление списка использует тот же `q`. Выбранная заявка остаётся открытой в чате, даже если её нет в результатах поиска. При создании новой заявки поле поиска очищается, чтобы новая заявка была видна.

#### Scenario: Поиск по части номера
- **WHEN** пользователь вводит «1910»
- **THEN** через короткую паузу запрашивается `GET /api/requests?q=1910`, в списке только заявки, в номере которых есть «1910»

#### Scenario: Одна пауза на несколько букв
- **WHEN** пользователь быстро вводит «0», «00», «000», «0002»
- **THEN** отправляется один запрос с `q=0002`

#### Scenario: Ничего не найдено
- **WHEN** по запросу нет заявок
- **THEN** показано «Ничего не найдено по запросу «7777»», сообщение «Заявок пока нет» не показывается

#### Scenario: Очистка
- **WHEN** пользователь нажимает кнопку очистки в поле поиска
- **THEN** запрашивается полный список без `q`

#### Scenario: Открытый чат при поиске
- **WHEN** открыт чат заявки, а пользователь ищет номер другой заявки
- **THEN** чат остаётся открытым, список показывает результаты поиска

#### Scenario: Новая заявка при поиске
- **WHEN** собственник создаёт заявку при непустом поле поиска
- **THEN** поле очищается, новая заявка видна в списке

### Requirement: Выделение заявок без ответа
Заявка с `awaiting_reply` (последнее сообщение написал собственник) SHALL выделяться в списке визуально: заметным цветом фона, цветной полосой слева и меткой «Ждёт ответа». Заявка, на последнее сообщение которой ответил администратор, остаётся без выделения и без метки. Выделение одинаково для собственника и администратора и не зависит от того, выбрана ли заявка (выбранная заявка дополнительно подсвечивается). После ответа администратора (в том числе полученного опросом) выделение пропадает, а после нового сообщения собственника появляется снова.

#### Scenario: Заявка без ответа
- **WHEN** в списке есть заявка, у которой `awaiting_reply` истинный
- **THEN** у неё цветной фон, полоса слева и метка «Ждёт ответа»

#### Scenario: Отвеченная заявка
- **WHEN** у заявки `awaiting_reply` ложный
- **THEN** фон обычный, метки нет

#### Scenario: Ответ администратора
- **WHEN** администратор отвечает в выделенной заявке
- **THEN** после обновления списка выделение с неё снимается

#### Scenario: Выбранная и выделенная
- **WHEN** выбрана заявка без ответа
- **THEN** она остаётся с меткой «Ждёт ответа» и дополнительно подсвечена как выбранная

### Requirement: Чат заявки
При выборе заявки справа SHALL открываться чат: шапка с номером заявки и (для администратора) квартирой и логином автора, лента сообщений и поле ввода. Если у сообщения есть вложения, под текстом показывается список файлов: значок типа, имя и размер («1,2 МБ», «340 КБ»); клик по файлу скачивает его с токеном входа (обычная ссылка токена не несёт), на время скачивания элемент показывает индикатор, а при ошибке появляется «Не удалось скачать файл». Сообщение без текста показывает только вложения. Сообщения идут по возрастанию времени, собственные выровнены вправо и визуально отличаются от чужих; у каждого видны автор («Вы», «Администрация» для администратора, логин собственника для администратора) и время. После открытия и после каждой отправки лента SHALL прокручиваться к последнему сообщению. Пока сообщения загружаются, показывается индикатор; ошибка — «Не удалось загрузить сообщения» с кнопкой «Повторить».

#### Scenario: Открытие чата
- **WHEN** собственник выбирает заявку с тремя сообщениями
- **THEN** справа номер заявки и три сообщения по возрастанию, свои справа, лента прокручена к последнему

#### Scenario: Автор сообщений для администратора
- **WHEN** администратор открывает заявку собственника `owner`
- **THEN** сообщения собственника подписаны «owner», свои — «Вы»

#### Scenario: Вложения в ленте
- **WHEN** в заявке есть сообщение с файлами `схема.pdf` (340 КБ) и `фото.jpg` (1,2 МБ)
- **THEN** под сообщением видны оба файла с именами и размерами, а клик по `схема.pdf` скачивает файл

#### Scenario: Ошибка скачивания
- **WHEN** запрос скачивания вложения завершается ошибкой
- **THEN** показано «Не удалось скачать файл»

#### Scenario: Автор сообщений для собственника
- **WHEN** собственник читает ответ администратора
- **THEN** сообщение подписано «Администрация»

#### Scenario: Ошибка загрузки сообщений
- **WHEN** запрос сообщений завершается ошибкой
- **THEN** показано «Не удалось загрузить сообщения» и кнопка «Повторить»

### Requirement: Отправка сообщения
Под лентой SHALL быть многострочное поле ввода, кнопка «Прикрепить файл» и кнопка «Отправить». Прикрепить можно до 5 файлов (JPEG, PNG, GIF, WebP, PDF, DOC, DOCX, XLS, XLSX, TXT) по 10 МБ, всего до 25 МБ; выбранные файлы показываются списком (имя, размер, кнопка удаления). Проверка выполняется до отправки: «Не более 5 файлов», «Файл «имя» больше 10 МБ», «Общий размер файлов больше 25 МБ», «Тип файла «имя» не поддерживается», «Файл «имя» пуст»; проблемный файл не добавляется, остальные остаются. Кнопка недоступна, пока нет ни текста (после обрезки пробелов), ни файла, и во время запроса; сообщение без текста с файлами допустимо; текст длиннее 2000 символов отклоняется сообщением «Сообщение длиннее 2000 символов». При отправке с файлами запрос уходит как `multipart/form-data`, без файлов — как JSON. Отправка возможна кнопкой и сочетанием Ctrl+Enter (Cmd+Enter), Enter без модификатора переносит строку. При успехе сообщение появляется в ленте, поле и список файлов очищаются, список заявок обновляется (заявка занимает место по общему порядку: после сообщения собственника она ждёт ответа, после сообщения администратора выходит из верхней группы). При ошибке текст и выбранные файлы сохраняются, над полем показывается сообщение: `413` — «Файл слишком большой или вложения превышают допустимый размер», `415` — «Тип файла не поддерживается», `404` — «Заявка недоступна», `403` — «Недостаточно прав», прочие — «Не удалось отправить сообщение. Попробуйте позже».

#### Scenario: Отправка
- **WHEN** собственник вводит «Подтекает кран» и нажимает «Отправить»
- **THEN** запрос `POST /api/requests/{id}/messages` отправлен, сообщение в ленте справа, поле пусто, список обновлён

#### Scenario: Пустой текст
- **WHEN** поле пусто или содержит только пробелы и файлов нет
- **THEN** кнопка «Отправить» недоступна

#### Scenario: Отправка с файлом
- **WHEN** собственник выбирает `схема.pdf` и нажимает «Отправить»
- **THEN** запрос `multipart/form-data` отправлен, сообщение с файлом появилось в ленте, список файлов очищен

#### Scenario: Только файл
- **WHEN** текст пуст, выбран один файл
- **THEN** кнопка «Отправить» доступна

#### Scenario: Шестой файл
- **WHEN** выбрано пять файлов и добавляется шестой
- **THEN** показано «Не более 5 файлов», шестой не добавлен, остальные остались

#### Scenario: Слишком большой файл
- **WHEN** выбирается файл больше 10 МБ
- **THEN** показано «Файл «имя» больше 10 МБ», файл не добавлен

#### Scenario: Неподдерживаемый тип
- **WHEN** выбирается файл `скрипт.exe`
- **THEN** показано «Тип файла «скрипт.exe» не поддерживается», файл не добавлен

#### Scenario: Удаление выбранного файла
- **WHEN** пользователь нажимает кнопку удаления у выбранного файла
- **THEN** файл исчезает из списка и не отправляется

#### Scenario: Ctrl+Enter
- **WHEN** пользователь нажимает Ctrl+Enter в заполненном поле
- **THEN** сообщение отправляется так же, как кнопкой

#### Scenario: Сбой сети
- **WHEN** запрос завершается ошибкой сети
- **THEN** показано «Не удалось отправить сообщение. Попробуйте позже», текст в поле сохранён

#### Scenario: Двойная отправка
- **WHEN** запрос ещё выполняется
- **THEN** кнопка недоступна и повторный запрос не отправляется

### Requirement: Новая заявка
Над панелями собственника, справа от заголовка «Заявки», SHALL быть кнопка «Новая заявка», открывающая окно с полем «Сообщение» (до 2000 символов), кнопкой «Прикрепить файл» (те же правила, ограничения и сообщения, что в чате) и кнопками «Создать» и «Отмена»; темы и названия у заявки нет, её номер присваивается сервером (см. спецификацию `requests-api`). Если у собственника несколько лицевых счетов, добавляется обязательный выбор квартиры, при одном счёте он подставляется без поля. Сообщение может быть пустым, только если выбран файл; пустое сообщение без файлов и превышение длины блокируют создание с сообщениями у поля («Введите сообщение», «Сообщение длиннее 2000 символов»). При успехе окно закрывается, заявка с присвоенным номером появляется в списке (как заявка без ответа, на месте по общему порядку) и открывается в чате; при ошибке окно остаётся открытым с введённым текстом и сообщением: `403` — «Недостаточно прав», `409` — «К вашей учётной записи не привязан лицевой счёт», `400` — «Проверьте сообщение», `413` — «Файл слишком большой или вложения превышают допустимый размер», `415` — «Тип файла не поддерживается», прочие — «Не удалось создать заявку. Попробуйте позже». Администратору и жильцу кнопки нет.

#### Scenario: Создание
- **WHEN** собственник вводит сообщение «Течёт кран» и нажимает «Создать»
- **THEN** окно закрывается, новая заявка с номером вида `О-ддммгг-NNNN` есть в списке с меткой «Ждёт ответа» и выделена как выбранная, справа её чат с этим сообщением

#### Scenario: Заявка с файлом
- **WHEN** собственник вводит сообщение, выбирает `фото.jpg` и нажимает «Создать»
- **THEN** отправлен `multipart/form-data`, заявка создана, в её чате первое сообщение с файлом

#### Scenario: Только файл
- **WHEN** сообщение пусто, выбран файл
- **THEN** кнопка «Создать» доступна

#### Scenario: Нет поля темы
- **WHEN** собственник открывает окно «Новая заявка»
- **THEN** в нём только поле «Сообщение» (и выбор квартиры при нескольких счетах), поля «Тема» нет

#### Scenario: Пустое сообщение
- **WHEN** сообщение не заполнено или состоит из пробелов
- **THEN** у поля «Введите сообщение», запрос не отправляется

#### Scenario: Ошибка сервера
- **WHEN** API отвечает ошибкой
- **THEN** окно остаётся открытым, текст сохранён, показано сообщение

#### Scenario: Отмена
- **WHEN** собственник нажимает «Отмена»
- **THEN** окно закрывается, заявка не создаётся

#### Scenario: Администратор
- **WHEN** вкладку открывает администратор
- **THEN** кнопки «Новая заявка» нет

### Requirement: Автообновление
Пока вкладка «Заявки» открыта и страница браузера видна, список заявок SHALL перезапрашиваться раз в 15 секунд, а открытый чат — раз в 5 секунд запросом `GET /api/requests/{id}/messages?after=<последний идентификатор>`; новые сообщения добавляются в ленту без перезагрузки, а лента прокручивается вниз, только если пользователь уже был у конца ленты. Фоновое обновление MUST NOT показывать индикатор загрузки, сбрасывать введённый текст и выбор заявки; ошибка фонового запроса молча пропускается до следующего раза. Опрос останавливается при уходе со вкладки, смене заявки, закрытии страницы и когда страница скрыта.

#### Scenario: Ответ приходит сам
- **WHEN** администратор отвечает в заявке, которую собственник держит открытой
- **THEN** в течение 5 секунд ответ появляется в ленте собственника без обновления страницы

#### Scenario: Ввод не теряется
- **WHEN** во время набора текста приходит обновление
- **THEN** набранный текст остаётся в поле

#### Scenario: Пользователь читает старое
- **WHEN** пользователь прокрутил ленту вверх, и приходит новое сообщение
- **THEN** сообщение добавлено в конец, лента не прокручивается

#### Scenario: Страница скрыта
- **WHEN** вкладка браузера скрыта
- **THEN** запросы обновления не отправляются

#### Scenario: Уход со вкладки
- **WHEN** пользователь переходит на другую вкладку приложения
- **THEN** опрос останавливается

### Requirement: Адаптивность
На широком экране (от 768 px) панели SHALL стоять рядом: список слева шириной около трети, чат справа. На узком экране показывается одна панель: список, а после выбора заявки — чат с кнопкой «К списку» в шапке; адрес с `request` на узком экране сразу открывает чат. Страница MUST NOT получать горизонтальную прокрутку.

#### Scenario: Узкий экран
- **WHEN** собственник открывает вкладку на экране 375 px
- **THEN** виден только список; после выбора заявки только чат с кнопкой «К списку»

#### Scenario: Возврат к списку
- **WHEN** пользователь нажимает «К списку»
- **THEN** снова виден список, выбор заявки снимается, `request` исчезает из адреса

#### Scenario: Широкий экран
- **WHEN** экран шире 768 px
- **THEN** список и чат видны одновременно

### Requirement: Статус заявки и кнопки администратора
Экран заявок SHALL показывать статус заявки русской меткой («Принята», «В работе», «Выполнена», «Закрыта») в заголовке чата и в строке списка. Администратору в заголовке чата показывается ровно одна кнопка перехода, соответствующая статусу: для `ACCEPTED` — «Взять в работу» (для заявки вида `VERIFICATION` — «Подтвердить»), для `IN_PROGRESS` — «Выполнено», для `DONE` — «Закрыть»; для `CLOSED` кнопок нет. Собственнику и жильцу кнопок перехода не показывается. Кнопка блокируется на время запроса; после успеха метка и кнопка обновляются без перезагрузки страницы, при ошибке показывается сообщение, статус остаётся прежним. В закрытой заявке поле ввода и кнопка отправки заблокированы с пояснением «Заявка закрыта». Номер заявки о проверке (начинается с «П») показывается как есть. В окне «Новая заявка» ничего не меняется: создаются только обычные заявки.

#### Scenario: Метка статуса
- **WHEN** открыт чат заявки в статусе `IN_PROGRESS`
- **THEN** в заголовке видна метка «В работе»

#### Scenario: Кнопка у администратора
- **WHEN** администратор открывает обычную заявку в статусе «Принята»
- **THEN** в заголовке есть кнопка «Взять в работу»; после нажатия метка «В работе» и кнопка «Выполнено»

#### Scenario: Подтвердить для заявки о проверке
- **WHEN** администратор открывает заявку `П-…` в статусе «Принята»
- **THEN** вместо «Взять в работу» показана кнопка «Подтвердить»

#### Scenario: Цепочка кнопок
- **WHEN** администратор нажимает «Взять в работу», «Выполнено», «Закрыть» по очереди
- **THEN** метки меняются на «В работе», «Выполнена», «Закрыта», после последней кнопок нет

#### Scenario: Нет кнопок у собственника
- **WHEN** собственник открывает свою заявку в любом статусе
- **THEN** кнопок перехода статуса нет, метка статуса видна

#### Scenario: Закрытая заявка
- **WHEN** открыта заявка в статусе «Закрыта»
- **THEN** поле ввода и отправка заблокированы, видно «Заявка закрыта»

#### Scenario: Ошибка перехода
- **WHEN** сервер ответил `409` на смену статуса
- **THEN** показано сообщение, данные заявки перезагружены, статус соответствует серверу
