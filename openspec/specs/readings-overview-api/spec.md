## Purpose

Описывает сводку показаний воды по всем квартирам для администратора: список месяцев (периодов передачи) и показания всех квартир за выбранный месяц, включая квартиры, не передавшие показания.

## Requirements

### Requirement: Список месяцев
Система SHALL предоставлять эндпоинт `GET /api/readings/periods`, возвращающий `{"periods": [...]}`: месяцы (периоды передачи показаний), за которые есть хотя бы одно показание, а также текущий период, даже если показаний за него ещё нет. Месяц — период передачи по правилам спецификации `meter-readings-api` (с днём закрытия `readings.period.closing-day`), названный по месяцу окончания: при дне закрытия 25 показание от 26 сентября относится к месяцу `2026-10`. Элемент: `month` (`ГГГГ-ММ`), `start` и `end` (первый и последний день периода, `ГГГГ-ММ-ДД`). Месяцы отсортированы от новых к старым, без повторов. Имена полей — в `snake_case`.

#### Scenario: Месяцы с показаниями и текущий
- **WHEN** показания есть за август и сентябрь 2026, а текущая дата 18 октября 2026
- **THEN** `periods` содержит `2026-10`, `2026-09`, `2026-08` именно в таком порядке

#### Scenario: Граница периода
- **WHEN** показание датировано 26 сентября 2026 (день закрытия 25)
- **THEN** оно относится к месяцу `2026-10`, а показание от 25 сентября — к `2026-09`

#### Scenario: Нет показаний
- **WHEN** в системе нет ни одного показания
- **THEN** ответ `200`, в `periods` только текущий период

#### Scenario: Границы месяца
- **WHEN** запрошен список месяцев
- **THEN** у `2026-10` `start` равен `2026-09-26`, `end` равен `2026-10-25`

### Requirement: Показания всех квартир за месяц
Система SHALL предоставлять эндпоинт `GET /api/readings?month=ГГГГ-ММ`, возвращающий `{"month": "...", "start": "...", "end": "...", "apartments": [...]}`. В `apartments` попадают все квартиры, у которых есть счётчики воды (квартиры без счётчиков не попадают), отсортированные по номеру квартиры (числа по возрастанию, затем остальные по строке), при равенстве по номеру лицевого счёта. Элемент квартиры: `account_number`, `apartment`, `address` (как в `GET /api/accounts`), `submitted` (сколько её счётчиков имеют показание за месяц), `total` (сколько у неё счётчиков) и `meters` (по номеру счётчика): `number`, `water_type` (`HOT` или `COLD`) и `reading` — объект `value`, `reading_date`, `previous_value` (значение предыдущего показания счётчика либо `null`), `consumption` (`value` минус `previous_value` либо `null`, если предыдущего нет) — либо `null`, если за месяц показания нет. Если у счётчика за месяц несколько показаний, берётся последнее (по дате, затем по порядку добавления). Показания — числа с тремя знаками после запятой. Ответ MUST NOT содержать технических полей (`id`, `is_test`). Ошибки: `400` — `month` отсутствует, не в формате `ГГГГ-ММ` или позже текущего периода.

#### Scenario: Квартира со сданными показаниями
- **WHEN** запрошен месяц, за который у квартиры 1 есть показания по обоим счётчикам
- **THEN** у неё `submitted` равен 2, `total` равен 2, у каждого счётчика заполнены `value`, `reading_date`, `previous_value` и `consumption`

#### Scenario: Квартира, не сдавшая показания
- **WHEN** за месяц у квартиры нет ни одного показания
- **THEN** квартира в списке, `submitted` равен 0, у всех её счётчиков `reading` равен `null`

#### Scenario: Сдан один счётчик из двух
- **WHEN** за месяц есть показание только по одному из двух счётчиков
- **THEN** `submitted` равен 1, `total` равен 2, у второго `reading` равен `null`

#### Scenario: Первое показание
- **WHEN** у счётчика за месяц первое показание и предыдущего нет
- **THEN** `previous_value` и `consumption` равны `null`

#### Scenario: Расход
- **WHEN** показание 245.300, предыдущее 230.000
- **THEN** `consumption` равен 15.300

#### Scenario: Квартира без счётчиков
- **WHEN** у квартиры нет счётчиков воды
- **THEN** её нет в `apartments`

#### Scenario: Порядок квартир
- **WHEN** есть квартиры 2, 10 и 1
- **THEN** порядок: 1, 2, 10

#### Scenario: Неверный месяц
- **WHEN** `month` отсутствует, равен `2026-13`, `октябрь` или месяцу после текущего периода
- **THEN** ответ `400`

#### Scenario: Месяц без показаний
- **WHEN** запрошен прошлый месяц, за который никто не сдавал показания
- **THEN** ответ `200`, все квартиры со счётчиками с `submitted` равным 0

### Requirement: Только для администратора
Эндпоинты `GET /api/readings/periods` и `GET /api/readings` SHALL требовать токен входа (`401` без него) и быть доступны только администратору; собственнику и жильцу ответ `403` без данных. Эндпоинты только читают данные.

#### Scenario: Администратор
- **WHEN** администратор запрашивает список месяцев и показания месяца
- **THEN** ответ `200`

#### Scenario: Собственник и жилец
- **WHEN** собственник или жилец запрашивает любой из эндпоинтов
- **THEN** ответ `403`, данных в теле нет

#### Scenario: Без токена
- **WHEN** запрос без токена
- **THEN** ответ `401`
