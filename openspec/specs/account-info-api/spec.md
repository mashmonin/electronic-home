## Purpose

Отдаёт клиентам информацию по лицевому счёту одним объектом: номер, адрес, помещение, совладельцы и счётчики воды с показаниями, по образцу ресурса `account` смежной системы.

## Requirements

### Requirement: Получение информации по лицевому счёту
Бэкенд SHALL предоставлять эндпоинт `GET /api/accounts/{number}`, возвращающий по номеру лицевого счёта один JSON-объект со статусом `200`. Объект MUST содержать поля:
- `number` — номер лицевого счёта строкой, ведущие нули сохраняются;
- `address` — адрес строкой вида «ул. Тестовая, д. Тест, кв. 1»;
- `premise` — объект с полями `street`, `house`, `apartment`;
- `owners` — список совладельцев счёта, каждый элемент содержит `full_name`;
- `meters` — список счётчиков воды квартиры счёта (состав элемента описан в требовании «Счётчики воды и показания в ответе»).

Имена полей MUST быть в `snake_case`.

#### Scenario: Существующий счёт
- **WHEN** клиент запрашивает `GET /api/accounts/000000000001` при наличии тестовых данных
- **THEN** ответ `200`, `number` равен `000000000001`, `address` равен «ул. Тестовая, д. Тест, кв. 1», `premise` содержит улицу «ул. Тестовая», дом «Тест» и квартиру «1»

#### Scenario: Несколько совладельцев
- **WHEN** у счёта два совладельца
- **THEN** `owners` содержит обоих, отсортированных по ФИО по возрастанию

#### Scenario: Счёт без совладельцев
- **WHEN** у существующего счёта нет совладельцев
- **THEN** `owners` — пустой список, статус `200`

### Requirement: Отсутствующий счёт
Если лицевого счёта с запрошенным номером нет, эндпоинт SHALL вернуть статус `404` без данных о других счетах.

#### Scenario: Неизвестный номер
- **WHEN** клиент запрашивает `GET /api/accounts/999999999999`, а такого счёта нет
- **THEN** ответ со статусом `404`

### Requirement: Только чтение
Эндпоинт MUST NOT изменять данные, а в ответе MUST NOT быть внутренних технических полей хранилища (идентификаторов записей, признака `is_test`).

#### Scenario: Состав ответа
- **WHEN** клиент получает информацию по счёту
- **THEN** в ответе нет полей `id` и `is_test`, а повторный запрос возвращает тот же результат

### Requirement: Доступность через прокси
Эндпоинт SHALL быть доступен клиентам по префиксу `/api` через nginx и, в профиле `dev`, из локального фронтенда по правилам CORS профиля.

#### Scenario: Запрос с локального фронтенда
- **WHEN** фронтенд на `http://localhost:5173` запрашивает эндпоинт в профиле `dev`
- **THEN** запрос не блокируется CORS

### Requirement: Счётчики воды и показания в ответе
Каждый элемент `meters` SHALL содержать поля:
- `number` — номер счётчика строкой;
- `water_type` — `HOT` для горячей воды или `COLD` для холодной;
- `verification_date` — дата окончания срока проверки счётчика (`ГГГГ-ММ-ДД`) либо `null`, если дата не задана; сервер MUST NOT вычислять по ней статус;
- `readings` — показания счётчика от новых к старым (по дате, затем по порядку добавления), где каждое показание содержит `value` (число), `reading_date` (дата `ГГГГ-ММ-ДД`) и `previous` — объект с `value` и `reading_date` предыдущего показания либо `null`, если предыдущего нет.

Счётчики SHALL быть отсортированы по номеру по возрастанию. В ответе MUST NOT быть технических полей хранилища (идентификаторов, `is_test`, ссылок на записи).

#### Scenario: Тестовые счётчики
- **WHEN** клиент запрашивает `GET /api/accounts/000000000001` при наличии тестовых данных
- **THEN** `meters` содержит «Тест 1» с `water_type` `HOT` и «Тест 2» с `water_type` `COLD`, именно в таком порядке

#### Scenario: Показания и предыдущее показание
- **WHEN** запрашивается счёт с тестовыми данными
- **THEN** у «Тест 1» первым в `readings` идёт показание `245.300` от 2026-09-25 с `previous` `{value: 230.000, reading_date: 2026-08-25}`, вторым — `230.000` от 2026-08-25 с `previous` `null`

#### Scenario: Квартира без счётчиков
- **WHEN** у квартиры счёта нет счётчиков
- **THEN** `meters` — пустой список, статус `200`

#### Scenario: Счётчик без показаний
- **WHEN** у счётчика нет показаний
- **THEN** его `readings` — пустой список

#### Scenario: Состав вложенных объектов
- **WHEN** клиент получает информацию по счёту со счётчиками
- **THEN** в `meters`, `readings` и `previous` нет полей `id` и `is_test`

#### Scenario: Даты проверки тестовых счётчиков
- **WHEN** запрашивается счёт с тестовыми данными
- **THEN** у «Тест 1» `verification_date` равен `2028-01-01`, у «Тест 2» — `2026-10-17`

#### Scenario: Счётчик без даты проверки
- **WHEN** у счётчика дата проверки не задана
- **THEN** его `verification_date` равен `null`
