## Purpose

Описывает форму входа на фронтенде, хранение сессии, обработку недействительной сессии, выход и интерфейс в зависимости от роли.

## Requirements

### Requirement: Форма входа
Фронтенд SHALL показывать форму входа всем неаутентифицированным пользователям: поле «Логин», поле «Пароль» (скрытый ввод) и кнопку «Войти», собранные из компонентов Ant Design. Кнопка MUST быть недоступна, пока одно из полей пусто, и во время выполнения запроса. Форма SHALL отправляться также клавишей Enter. Вёрстка MUST корректно работать на узком (мобильном) экране.

#### Scenario: Неаутентифицированный пользователь
- **WHEN** пользователь без сохранённой сессии открывает приложение
- **THEN** он видит форму входа, экран показаний и данные счёта не показываются

#### Scenario: Пустые поля
- **WHEN** логин или пароль не заполнены
- **THEN** кнопка «Войти» недоступна

#### Scenario: Отправка с клавиатуры
- **WHEN** пользователь заполнил оба поля и нажал Enter
- **THEN** выполняется вход так же, как по нажатию кнопки

### Requirement: Результат входа
При успешном входе фронтенд SHALL сохранить токен для текущей вкладки браузера, запросить `GET /api/auth/me` и открыть экран показаний. При ответе `401` форма MUST остаться открытой и показать сообщение «Неверный логин или пароль», пароль очищается, логин сохраняется. При сетевой ошибке или ответе `5xx` форма MUST показать сообщение «Не удалось выполнить вход. Попробуйте позже».

#### Scenario: Верные данные
- **WHEN** пользователь вводит верные логин и пароль
- **THEN** открывается экран показаний его лицевого счёта

#### Scenario: Неверные данные
- **WHEN** API отвечает `401` на вход
- **THEN** показано сообщение «Неверный логин или пароль», поле пароля пусто, логин не изменён

#### Scenario: Ошибка связи
- **WHEN** запрос входа завершается сетевой ошибкой
- **THEN** показано сообщение «Не удалось выполнить вход. Попробуйте позже»

### Requirement: Сессия на клиенте
Токен SHALL храниться в `sessionStorage` вкладки и добавляться заголовком `Authorization: Bearer` ко всем запросам к `/api`, кроме входа. После перезагрузки страницы в той же вкладке пользователь MUST оставаться вошедшим, пока токен не истёк. Токен MUST NOT попадать в адресную строку, журнал консоли и `localStorage`.

#### Scenario: Перезагрузка страницы
- **WHEN** вошедший пользователь перезагружает страницу в той же вкладке
- **THEN** он остаётся на экране показаний без повторного ввода пароля

#### Scenario: Новая вкладка
- **WHEN** пользователь открывает приложение в новой вкладке
- **THEN** ему показана форма входа

### Requirement: Недействительная сессия
Если любой запрос к `/api`, кроме входа, завершается `401`, фронтенд SHALL удалить токен и показать форму входа с сообщением «Сессия истекла. Войдите снова». Ответ `403` MUST NOT сбрасывать сессию, а показывает сообщение «Недостаточно прав».

#### Scenario: Токен истёк
- **WHEN** во время работы API отвечает `401` на запрос данных
- **THEN** токен удалён, показана форма входа с сообщением «Сессия истекла. Войдите снова»

#### Scenario: Нет прав
- **WHEN** API отвечает `403` на запрос данных
- **THEN** сессия сохраняется, пользователь видит сообщение «Недостаточно прав»

### Requirement: Выход
Шапка экрана SHALL содержать действие «Выйти», доступное из меню профиля. При выходе токен MUST удаляться из `sessionStorage`, данные счёта сбрасываться, а пользователь — видеть форму входа.

#### Scenario: Выход
- **WHEN** пользователь выбирает «Выйти»
- **THEN** токен удалён, показана форма входа, кнопка «Назад» браузера не возвращает данные счёта без входа

### Requirement: Интерфейс по роли
Фронтенд SHALL скрывать вкладку «Квитанции» от роли `RESIDENT`. Скрытие является удобством: доступ MUST по-прежнему проверяться сервером.

#### Scenario: Жилец
- **WHEN** в систему вошёл жилец
- **THEN** вкладка «Квитанции» отсутствует в навигации

#### Scenario: Собственник
- **WHEN** в систему вошёл собственник
- **THEN** вкладки «Показания» и «Квитанции» доступны
