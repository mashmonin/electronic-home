## Purpose

Определяет два профиля приложения — `dev` для локальной разработки и `prod` для промышленной эксплуатации — и их обязательные различия.

## Requirements

### Requirement: Выбор профиля при запуске
Приложение SHALL запускаться ровно в одном из профилей `dev` или `prod`. Если профиль не задан, приложение MUST отказаться стартовать с понятным сообщением об ошибке.

#### Scenario: Запуск без профиля
- **WHEN** приложение запускается без указания профиля
- **THEN** старт завершается ошибкой, в сообщении указаны допустимые профили `dev` и `prod`

#### Scenario: Запуск с допустимым профилем
- **WHEN** приложение запускается с профилем `dev` или `prod`
- **THEN** приложение стартует и применяет настройки выбранного профиля

### Requirement: Поведение профиля dev
Профиль `dev` SHALL быть удобным для разработки: подробное логирование (DEBUG для кода приложения), разрешённый CORS для локального адреса фронтенда, учётные данные БД по умолчанию из dev-окружения.

#### Scenario: Подробные логи в dev
- **WHEN** приложение работает в профиле `dev`
- **THEN** сообщения уровня DEBUG кода приложения попадают в лог

### Requirement: Поведение профиля prod
Профиль `prod` SHALL быть безопасным по умолчанию: логирование не ниже INFO, отсутствие значений по умолчанию для паролей и секретов, детали ошибок не раскрываются клиенту. Все секреты MUST передаваться через переменные окружения или секреты контейнера.

#### Scenario: Отсутствует пароль БД в prod
- **WHEN** приложение запускается в профиле `prod` без заданного пароля БД
- **THEN** старт завершается ошибкой, значение по умолчанию не используется

#### Scenario: Ошибки не раскрывают внутренности
- **WHEN** в профиле `prod` обработка запроса завершается внутренней ошибкой
- **THEN** клиент получает общий ответ об ошибке без стека и внутренних деталей

### Requirement: Секрет подписи токенов
Профиль `prod` SHALL требовать секрет подписи JWT из переменной окружения или секрета контейнера без значения по умолчанию; секрет MUST быть не короче 32 байт. Если секрет не задан или короче, старт MUST завершаться ошибкой. Профиль `dev` SHALL иметь значение секрета по умолчанию, пригодное только для разработки.

#### Scenario: Нет секрета в prod
- **WHEN** приложение запускается в профиле `prod` без секрета подписи
- **THEN** старт завершается ошибкой, значение по умолчанию не используется

#### Scenario: Короткий секрет в prod
- **WHEN** в профиле `prod` задан секрет короче 32 байт
- **THEN** старт завершается ошибкой

#### Scenario: Запуск dev без настройки
- **WHEN** приложение запускается в профиле `dev` без переменных окружения для токенов
- **THEN** приложение стартует, вход тестовым пользователем работает
