# Электронный дом

Веб-сервис для жильцов и управляющей организации многоквартирного дома: передача показаний счётчиков воды, квитанции ЖКУ и обращения в виде чатов.

Собственник вводит показания раз в период и скачивает свои квитанции. Администратор загружает ведомость начислений, и сервис сам формирует PDF-квитанции для каждого лицевого счёта.

## Возможности

- **Передача показаний воды**: период с 26-го по 25-е число, после сдачи поле счётчика закрыто до следующего периода, повторная отправка отклоняется.
- **Квитанции**: PDF по каждому счёту и месяцу, суммы по капитальному ремонту и коммунальным услугам, скачивание через бэкенд с проверкой прав.
- **Квитанции из ведомости начислений**: администратор загружает `.xls`, сервис в фоне формирует и публикует квитанции всех квартир, ход виден в интерфейсе.
- **Заявки как чаты**: номер вида `О-191026-0001`, вложения до 5 файлов, заявки без ответа всегда сверху, поиск по номеру.
- **Счётчики**: смена даты очередной поверки с актом, сводная таблица всех показаний для администратора.
- **Роли**: `ADMIN`, `OWNER`, `RESIDENT`, вход по логину и паролю (JWT).
- **Своё S3-хранилище** для файлов (SeaweedFS), анонимного доступа и прямых ссылок наружу нет.
- **Импорт** собственников, счетов и показаний из таблиц; персональные данные остаются вне git.

## Стек

| Слой | Технологии |
|---|---|
| Backend | Java 21, Spring Boot 4.1, Spring Security (JWT), Spring Data JPA, Liquibase, Apache POI, OpenPDF |
| Frontend | React 19, TypeScript, Vite, Ant Design, Vitest |
| База данных | PostgreSQL, схема только через Liquibase |
| Файлы | SeaweedFS (S3 API) |
| Инфраструктура | Docker Compose, nginx с HTTPS |

Архитектура: слоистая (controller / service / repository), REST API только с JSON, профили `dev` и `prod`.

## Быстрый старт

Нужен только Docker с Compose. JDK, Node.js и PostgreSQL на машине не нужны.

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

Приложение откроется на https://localhost (сертификат самоподписанный, браузер предупредит). Фронтенд работает через Vite с HMR, правки в `frontend/` подхватываются без пересборки.

Остановка и полная очистка:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml down -v
```

Тесты:

```bash
cd backend && ./gradlew test      # нужен Docker для Testcontainers
cd frontend && npm ci && npm test
```

Запуск бэкенда из IDE, продакшен-развёртывание, настройки периода, хранилища, ролей и API описаны в [`docs/OPERATIONS.md`](docs/OPERATIONS.md).

## Структура репозитория

```
backend/    Spring Boot API (Gradle wrapper внутри)
frontend/   Vite + React + TypeScript
infra/      конфиги nginx и сертификаты
tools/      скрипты импорта собственников
openspec/   спецификации и история изменений
docs/       эксплуатационная документация
```

## Разработка по спецификациям

Проект ведётся по spec-driven подходу с [OpenSpec](https://github.com/Fission-AI/OpenSpec). Нетривиальные изменения сначала оформляются как proposal, затем реализуются и архивируются. Актуальное поведение системы описано в [`openspec/specs/`](openspec/specs/): аутентификация и роли, показания, квитанции, заявки, вложения, хранилище, импорт и другие области.
