# Импорт собственников, лицевых счетов и логинов

Скрипт читает ведомость начислений (`.xls`) и берёт из неё только номер лицевого счёта, ФИО собственника и квартиру.
Суммы, площади, тарифы и реквизиты не используются. Всё, что содержит персональные данные, пишется в `data/`
(в `.gitignore`) и в git не попадает.

## Подготовка

```bash
python3 -m venv .venv && .venv/bin/pip install -r tools/owners-import/requirements.txt   # нужен htpasswd (Apache utils)
.venv/bin/python tools/owners-import/generate.py "/путь/к/сентябрь_2026.xls"
.venv/bin/python -m unittest discover -s tools/owners-import                              # проверка самого скрипта
```

Скрипт сначала проверяет файл на чувствительные данные (e-mail, личные телефоны, СНИЛС, паспорт, дата рождения;
значения не печатаются) и останавливается, если что-то нашёл (`--allow-sensitive`, чтобы продолжить осознанно). Он также
останавливается, если у двух разных людей получился один логин или ФИО состоит не из трёх слов. Организации и офисы
пропускаются, их список виден в отчёте.

Результат в `data/` (права 600):

| Файл | Что внутри |
|---|---|
| `migrations/021-import-owners.sql` | собственники, счета, логины и BCrypt-хеши (идемпотентно) |
| `migrations/021-import-owners.rollback.sql` | удаление того, что создал импорт |
| `credentials/owner-passwords.csv` | `логин;пароль;счета` — транспортные пароли для выдачи |

Логин: первая буква имени + первая буква отчества + фамилия, латиницей строчными (Шмонин Андрей Александрович →
`aashmonin`). Собственник с несколькими счетами получает одну учётную запись на все счета. Пароль — 12 случайных
знаков; принудительной смены при первом входе нет.

## Применение на сервере (один раз)

1. Скопировать `data/migrations/` на сервер и сделать резервную копию БД.
2. Запустить backend с контекстом импорта и каталогом файлов:
   ```bash
   LIQUIBASE_CONTEXTS=prod,owners-import OWNERS_IMPORT_DIR=/путь/к/migrations docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env.prod up -d backend
   ```
3. Убедиться, что changeset `021-import-owners` выполнен, затем вернуть обычный запуск (без `LIQUIBASE_CONTEXTS`,
   changeset уже записан в `databasechangelog`).
4. Передать собственникам логины и пароли из `owner-passwords.csv`, после выдачи удалить файл и `migrations/` с сервера.

Квартиры 1–138 должны уже быть в базе (миграция 020): иначе импорт остановится с ошибкой и ничего не запишет.
Откат: `021-import-owners.rollback.sql` (на `prod` надёжнее восстановить копию БД).
